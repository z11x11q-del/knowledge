## 核心命题

> 你不再需要擅长写提示词。你需要擅长的是 **那个替你发提示词的循环**。五大构件外加状态，共同构成了一个循环：**automations、worktrees、skills、plugins、sub-agents**。

**核心循环**：自动化 → 隔离 → 技能 → 连接 → 验证

---

## 循环工程为何不同

循环工程是 **取代你自己作为提示 Agent 的人**。你转而设计替你做这件事的系统。

> "你不再应该给编码 Agent 发提示词了。你应该设计给 Agent 发提示词的循环。"
> —— **Peter Steinberger**

> "我已经不再直接给 Claude 发提示词了。我跑着让 Claude 发提示词、并且自己想办法解决问题的循环。我的工作就是写这些循环。"
> —— **Boris Cherny**，Anthropic Claude Code 负责人

> 大概两年来，你从编码 Agent 里拿到价值的方式是：写一条好提示词，分享足够的上下文，读它返回的内容，再敲下一句。整个过程，Agent 是工具，你全程握着它，一轮又一轮。这一段已经差不多结束了，或者至少有人认为它会结束。
>
> 现在的做法是：你搭一个小系统，它发现工作、分派任务、验收结果、记下完成项、决定下一步，让这个系统去戳 Agent，而不是你自己去戳。**循环工程位于 harness 之上。** 那条按定时器跑的 harness，派生出小帮手，自己喂自己。

## 四大特征

### 01 — 真正的反馈循环
Agent 提出改动、运行实验、读取结果，只保留能改善结果的点子。

### 02 — 不仅仅是自动化
Automations 负责按计划执行发现与分诊。**它是让循环真正成为循环的心跳**，而不只是一次性运行。

### 03 — Skills 沉淀知识
Skill 是写在 `SKILL.md` 里的项目知识，让 Agent 不用每轮都从零推导意图。

### 04 — 子 Agent 负责校验
最有用的结构性做法：**写的人与查的人分开**。写出代码的模型在批改自己作业时手太软。

## 五大构件（外加状态）

一个循环需要 **五样东西**，再加 **一个地方记住事情**。下面的形态在 Codex、Claude Code 以及跟随它们的每一个工具中通用。

| # | 构件 | 在循环中的职责 |
| :--: | :-- | :-- |
| 1 | **Automations** | 按计划完成发现与分诊 |
| 2 | **Worktrees** | 隔离并行任务 |
| 3 | **Skills** | 沉淀项目知识 |
| 4 | **Plugins / Connectors** | 连接你的工具 |
| 5 | **Sub-Agents** | 提出想法并校验 |
| 6 | **State（记忆）** | 记录已完成的事项 |

### 1. Automations
Automations 让循环真正成为"循环"，而不是"只跑过一次的运行"。定义一个自治任务，给它一个节奏，让发现自动送上门来。

### 2. Worktrees
一旦运行不止一个 Agent，文件就会开始打架。Git worktree 就是解药——一个独立的 working directory、独占分支，共享同一份仓库历史。

### 3. Skills
Skill 是让你不再每轮重复解释同一份项目上下文的办法。Claude Code 与 Codex 都使用一个包含 `SKILL.md` 的文件夹，里面放着指令与元数据。

### 4. Plugins & Connectors
一个只能看文件系统的循环是个极小的循环。基于 MCP 构建的连接器让 Agent 读你的工单系统、查数据库、或在 Slack 里发消息。

### 5. Sub-Agents
第二个拥有不同指令、有时甚至不同模型的 Agent，能抓住第一个把自己说服的地方。**作者与检查者，分开。**

### 6. State（记忆）
一个 Markdown 文件或一块 Linear 看板——任何处在单次会话之外、记录着"已完成"和"接下来"的东西。**模型在每次运行之间遗忘；仓库不会。**

## 一个循环如何运转

把这些拼起来，单一线程就变成一个小控制面板。下面是反复出现的形态。

### 01 — 一条 Automation 每天早晨运行
它的提示词调用 **分诊 skill**，读取昨日 CI 失败、开放 issue、最近提交，把发现写到 Markdown 文件或 Linear 看板。

### 02 — 为每个修复隔离 worktree
对每一条值得做的发现，线程开一个隔离的 worktree，派一个子 Agent 起草修复，再派第二个子 Agent 按项目 skills 与既有测试审阅草稿。

### 03 — 连接器把循环闭环
连接器让循环开 PR、更新工单。处理不掉的落到分诊收件箱。状态文件记得哪些试过、哪些通过、哪些还开着。

### 04 — 你只设计一次
以上步骤你没有亲手写过任何提示词。这正是 Steinberger 整句话的落地，无论在 Codex 还是 Claude Code 上，循环都一样，因为构件都一样。

## 循环仍然不能替你做的事

循环改变了工作。**但它没有把你从中删除。** 三个问题反而会随着循环越变越好而越变越尖锐。

### 验证仍然在你手上
一个无人值守的循环就是一个无人值守地制造错误的循环。**你的工作是交付你确认过能跑起来的代码。**

### 你的理解仍然在腐烂
循环越快地产出你没写过的代码，存在与你真正理解之间的鸿沟就越大。**读一读循环写出的东西。**

### 认知投降是真实的
当循环自己跑起来，停止持有观点是巨大的诱惑。**带着判断力设计循环是解药，逃避思考地设计循环是催化剂。**

> **搭起循环。但要像一个打算继续做工程师的人那样去搭，而不是像一个只会按启动键的人。**

## FAQ

### 什么是循环工程？
为编码 Agent 设计自动提示系统的实践，而不是手动提示。循环负责发现工作、分派任务、校验输出、追踪完成项——整个过程不需要你盯着。

### 五大构件是什么？
Automations、Worktrees、Skills、Plugins/Connectors、Sub-Agents，外加第六项：**状态或记忆**，存放在会话之外。

### 与提示词工程的区别？
提示词工程关心如何写好一条提示词。循环工程关心如何设计一个你根本不再需要写单条提示词的、由系统代劳的循环。

### 哪些工具支持循环工程？
OpenAI Codex 与 Claude Code 都内置了五大构件。命令名略有差异，但能力对等。在一方设计的循环能在另一方几乎无缝运行。

### 我还需要 review 代码吗？
需要。**验证是循环中最重要的人类角色。** 一个无人值守的循环就是一个无人值守地制造错误的循环。
