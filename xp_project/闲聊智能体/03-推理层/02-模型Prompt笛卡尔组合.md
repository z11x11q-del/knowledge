### 2.5 模型 × Prompt 笛卡尔组合

**能力定位**：通过构建「模型池 × Prompt 池」的组合矩阵，实现多实验并行、灵活调度。同时，针对不同垂域（sub_intent）实施差异化的 Prompt 上下文策略，是这一模块的核心复杂度所在。

---

#### 一、组合矩阵

**组合矩阵示例**：

```
模型池                    Prompt 池
────────────              ──────────────────
M1: GPT-4o          ×    P1: 温柔姐姐人设
M2: 文心一言 4.5    ×    P2: 活泼朋友人设
M3: 端侧小模型      ×    P3: 专业助理人设
                          P4: 幽默段子手人设

笛卡尔积 → 12 个候选配置（M×P combinations）
```

**路由调度策略**：

```
请求进入推理层
    ↓
读取 AB 实验分桶 → 确定当前用户命中哪个实验组
    ↓
实验组配置 = {model_id: "M1", prompt_id: "P2"}
    ↓
按 sub_intent 做 Prompt 精调：
    - emotion_chat → Prompt 加入“共情引导”片段
    - joke        → Prompt 加入“幽默模式”片段
    - math        → Prompt 加入“思维链 + 禁止编造”片段
    - story       → Prompt 加入“叙事结构”片段
    ↓
最终 Prompt = Base 人设 + 垂域片段 + 上下文片段 + 当前 Query
```

**组合配置管理**：

```yaml
# 配置中心，支持热更新
combinations:
  - id: "combo_001"
    model: "gpt-4o"
    prompt_template: "persona_warm_sister"
    ab_group: "exp_A"
    weight: 0.3         # 流量占比

  - id: "combo_002"
    model: "ernie-4.5"
    prompt_template: "persona_funny_friend"
    ab_group: "exp_B"
    weight: 0.3

  - id: "combo_base"
    model: "ernie-4.5"
    prompt_template: "persona_default"
    ab_group: "control"
    weight: 0.4
```

#### 二、垂域差异化的 Prompt 上下文策略

> 这是本模块的核心复杂度：**Prompt 不是平铺的全量上下文，而是按垂域定制的策略拼装**。

**Prompt 分段结构**：

```
最终 Prompt = [Base 人设]
              + [Sub_intent 垂域片段]
              + [Context 片段（按垂域定制）]
              + [System 信息片段（时间/天气等如有）]
              + [Query]
```

其中 **Context 片段**是各垂域差异最大的地方——不同垂域需要的历史轮次、信息粒度、压缩策略完全不同。

**各垂域上下文策略对比**：

| 垂域 / 标签 | Context 深度 | 关键信息 | 压缩策略 | Token 预算占比 |
|----------|------------|---------|---------|----------------|
| `emotion_chat` | 高（全量轮次） | 用户情绪状态、说过的每一件事 | **不压缩**，压缩会丢失情感细节 | 40~60% |
| `qa_knowledge` | 中（话题线索） | 当前话题主线、已展开子问题 | 旧轮次摘要压缩，保话题线索不打断 | 20~30% |
| `math` | 低（仅当前题目） | 题目完整条件和约束 | **清空历史轮次**，防止干扰推理 | 5~10% |
| `date_calc` | 几乎不需要 | 当前 Query | 不带历史，主要靠工具返回内容 | < 5% |
| `joke` | 低（最近20轮） | 最近讲过的笑话类型 | 符号化压缩，仅防重复 | 10~15% |
| `story` | 中高（已有情节） | 已建立的人物、情节进展、未解决冒险 | 摘要原文保留情节骨架 | 30~40% |
| `poetry` | 低（仅格律/风格要求） | 格律要求、主题、风格偏好 | 不带历史轮次，仅保留要求约束 | < 10% |
| `casual_chat` | 中（滑动窗口） | 近几轮话题连贯性 | 滑动窗口保留最近N轮 | 20~25% |
| `web_*` | 低（主要靠检索结果） | 当前 Query意图 | 少用历史，大部分 token 留给检索结果 | 10~15% |

**关键设计点**：

1. `emotion_chat` 是**唯一不能压缩**的垂域，情感话题的历史信息密度高、细节重要。一旦摘要，“你还记得我说的吗”就会发生。

2. `math` 反而要清空历史，因为旧轮次的内容会干扰数学推理的动势，导致模型沿着上一轮的错误方向继续推理。

3. `story` 的压缩是“情节骨架摘要”，而非通用摘要——保留“主角、动机、未结技线”，丢弃对话细节和环境描写。

4. `joke` 的上下文不是“记忆内容”，而是“多样性控制”——用来避免连续讲同一类型的笑话，而不是为了情境理解。

**Prompt 内存压力与分配选择**：

```
总 token 预算 = 模型 Context Window 的 50~60%（剩余用于生成）

分配优先级：
  优先 1：Base 人设（固定，不可剪）
  优先 2：垂域片段（固定，不可剪）
  优先 3：当前 Query（固定）
  优先 4：历史上下文（按垂域策略和数量裁减）
  优先 5：外部检索结果（web_* 垂域优先，其他垂域不占）

当历史上下文超出预算时：
  emotion_chat → 只剪远期轮次，不剪近期
  qa_knowledge → 摘要各轮主要观点
  其他垂域  → 平均裁减最早轮次
```

---

#### 三、关键决策

- Prompt 采用**模板分段设计**（Base + 垂域片段 + 上下文片段），避免全量 Prompt 膨胀，片段可独立迭代
- 新 combo 上线时先走**灰度流量（1%→5%→20%）**，指标达标后再放量，防止劣化配置大面积影响用户
- 模型间的**价格/质量/延迟三角**纳入路由权重，低峰期可多用大模型；高峰期自动切到小模型降本
- `emotion_chat` 的上下文资源占用**显著高于其他垂域**，高峰期可单独为其分配更大的模型 Context Window

**答辩问答预设**：

> Q：笛卡尔组合数量爆炸怎么办，不可能把所有组合都跑一遍 AB？
> A：对，实际上我们采用**分阶段淘汰**策略：先用小流量快速过滤明显差的组合，再把胜出的 top-K 进入下一轮精细对比。本质上是个多臂赌博机（MAB）问题，用 UCB 或 Thompson Sampling 做流量分配，收敛速度比纯 AB 快 3~5 倍。

> Q：不同垂域上下文策略不一样，指的是什么？
> A：核心差异在于历史轮次的「深度」和「压缩方式」两个维度。情感陪伴需要全量轮次且不能压缩，否则用户感受到“被遗忘”；数学题反而要清空历史，防止历史错误内容误导当前推理；讲故事等同一个垂域内部也有差异——故事的压缩是「情节骨架摘要」而非通用摘要。这些设计就是为什么不能用一套统一的上下文策略完事的原因。

> Q：上下文资源卷大了怎么办， Context Window 满了？
> A：优先级切割。Base 人设、垂域片段、当前 Query 不可剪；历史上下文按各垂域策略裁减， emotion_chat 只剪远期轮次，其他垂域平均裁减最早轮次。长远来看 Context Window 尺度增大是趋势，但当前阶段精细上下文策略 > 单纯依赖扩大尺度。
