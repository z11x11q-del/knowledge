# 记忆架构：Online Memory + Offline Profiling 混合设计

> 闲聊智能体记忆子系统设计文档
> 关联模块：06-基础能力/01-多轮上下文管理.md、06-基础能力/02-个性化与用户画像.md
> 本文档在基础能力基础上，给出完整的混合记忆架构方案

---

## 1. 为什么需要混合架构

纯 Online Memory 的问题：
- Session 结束后记忆消失，用户每次都像"第一次见面"
- 无法累积用户偏好，个性化全靠当轮推断，不稳定

纯 Offline Profiling 的问题：
- 离线批处理有延迟（T+1 甚至 T+7），今天的情绪昨天的画像感知不到
- 无法捕捉当前 Session 的实时上下文，回复缺乏即时感

**混合架构的核心思路**：

```
Online Memory   → 感知"现在"：当前 Session 发生了什么
Offline Profile → 理解"过去"：这个用户是什么样的人
两者融合注入 Prompt → 回复既有上下文连贯性，又有长期个性化
```

---

## 2. 整体架构

```
用户请求
    ↓
┌─────────────────────────────────────────────────────────┐
│  记忆读取层（推理前）                                    │
│  ├─ [L1] Session Memory   → 当前 Session 实时上下文      │
│  ├─ [L2] Recent Memory    → 近 7 天跨 Session 记忆       │
│  └─ [L3] Offline Profile  → 长期用户画像（T+1 更新）     │
└───────────────────────────┬─────────────────────────────┘
                            ↓
                    记忆融合 & Prompt 注入
                            ↓
                      LLM 推理 & 回复
                            ↓
┌─────────────────────────────────────────────────────────┐
│  记忆写入层（推理后，异步）                              │
│  ├─ 实时写入：当轮对话追加到 Session Memory              │
│  ├─ Session 结束：关键信息抽取 → 写入 Recent Memory      │
│  └─ 离线批处理：历史对话 → 更新 Offline Profile（T+1）   │
└─────────────────────────────────────────────────────────┘
```

## 3. Online Memory 设计

### 3.1 两层结构

**L1 — Session Memory（会话记忆）**

```
生命周期：当前 Session（30 分钟无活跃自动关闭）
存储介质：Redis（热存储，低延迟读取）
数据内容：
  - 完整对话轮次（raw turns）
  - 实时情绪状态（joy/sad/anxious/neutral）
  - 当前话题线程（topic_thread）
  - 本轮已提取的实体（entities）
TTL：Session 结束后保留 2 小时（供 Session 结束处理任务读取）
```

**L2 — Recent Memory（近期记忆）**

```
生命周期：7 天滚动窗口
存储介质：Redis（较低频读取，可降级到 RDB 持久化）
数据内容：
  - 近期发生的重要事件摘要（"上次说要去看演唱会"）
  - 近期表达过的偏好信号（"不喜欢被催"）
  - 近期情绪趋势（连续 3 天倾诉负面情绪）
  - 近期话题偏好（最近频繁聊电影）
更新时机：每个 Session 结束时，异步写入
```

### 3.2 写入策略

```
实时写入（每轮对话同步）：
  - 当轮 Q/A 追加到 Session Memory
  - 更新实时情绪状态（轻量分类器，< 5ms）
  - 更新话题线程（关键词+实体提取）

Session 结束异步写入（Post-Session Processing）：
  1. 调用摘要模型 → 提取本次 Session 的关键事件 / 偏好信号
  2. 过滤低价值信息（问候、重复内容）
  3. 写入 L2 Recent Memory
  4. 标记本 Session 状态（情绪总体 / 话题分布）
```

### 3.3 读取策略

```
Session 开始时：
  1. 加载 L2 Recent Memory（摘要形式，限 500 token）
  2. 加载 L3 Offline Profile（背景知识，限 200 token）
  3. 初始化 L1 Session Memory（空）

Session 进行中（每轮推理前）：
  1. L1 Session Memory 实时更新，直接作为对话历史
  2. L2/L3 在 Session 开始时已注入，不重复读取（减少延迟）

特殊触发：
  - 用户提及过去事件（"上次你说…"）→ 实时检索 L2 相关片段补充
  - 情绪骤变检测（上轮正常，本轮悲伤）→ 主动注入情绪陪伴提示
```

## 4. Offline Profiling 设计

### 4.1 用户画像数据模型

```json
{
  "user_id": "u_xxx",
  "updated_at": "2026-05-28",

  "stable_preferences": {
    "humor_style": "冷笑话",
    "topic_interests": ["电影", "科技", "音乐"],
    "communication_style": "随意口语化",
    "response_length_pref": "短回复"
  },

  "behavioral_patterns": {
    "avg_session_length_turns": 8,
    "active_hours": "21:00-23:00",
    "dominant_intent_dist": {
      "emotion_chat": 0.45,
      "casual_chat": 0.30,
      "qa_knowledge": 0.15,
      "joke": 0.10
    },
    "multi_turn_depth": "深度追问型"
  },

  "known_facts": [
    {"fact": "喜欢周杰伦", "confidence": 0.92, "first_seen": "2026-04-10"},
    {"fact": "最近在备考", "confidence": 0.78, "first_seen": "2026-05-20"},
    {"fact": "不喜欢被催促", "confidence": 0.85, "first_seen": "2026-03-15"}
  ],

  "emotional_baseline": {
    "typical_mood": "平静偏积极",
    "stress_triggers": ["工作压力", "人际关系"],
    "comfort_topics": ["音乐", "回忆过去快乐的事"]
  }
}
```

### 4.2 离线信息提取流水线

```
每日凌晨批处理任务：

输入：过去 30 天的历史对话日志（按 user_id 聚合）
    ↓
[过滤] 过滤低信息量对话（短于 3 轮、兜底 casual_chat）
    ↓
[抽取] LLM 提取器（GPT-4 级别）：
  - 用户明确表达的偏好（"我喜欢/不喜欢…"）
  - 用户隐含的偏好（连续 10 次问科技问题 → 科技兴趣偏高）
  - 生活事件（"我最近在准备婚礼"）
  - 情绪模式（近 7 天负面情绪频率）
    ↓
[置信度评分] 每条 fact 附置信度（出现频次 × 时间衰减系数）
    ↓
[合并去重] 与现有画像合并，低置信覆盖高置信需人工确认
    ↓
[写入] 更新 Offline Profile DB（PostgreSQL + 向量索引）
```

### 4.3 Known Facts 的检索机制

Known Facts 不是全量注入 Prompt，而是**按相关性检索后按需注入**：

```
推理时：
  1. 将当前 Query 向量化
  2. 检索 Known Facts 向量库，取 Top-3 相关 facts
  3. 仅将相关 facts 注入 Prompt，避免无关信息干扰

例：用户问"今天心情不好" → 检索到 "comfort_topics: 音乐/回忆"
     → 注入提示：可以引导用户聊音乐或积极回忆
```

### 4.4 离线记忆处理：压缩、归纳与蒸馏

> 原始对话是噪声密集的流式文本，直接存储成本高、检索精度低。离线记忆处理的核心任务是：**把情节性的对话事件，逐级压缩、归纳成稳定的语义知识**。

#### 4.4.1 三级摘要体系

```
原始对话轮次（Raw Turns）
        ↓  Session 结束时
    Session 摘要（~100 token）       ← L2 写入
        ↓  每周批处理
    近期模式归纳（~200 token）       ← L2 更新
        ↓  每日 T+1 批处理
    长期画像更新（结构化 JSON）       ← L3 更新
```

**Level 1 — Session 压缩**（Session 结束后异步触发）

```
输入：当次 Session 原始对话轮次
目标：提取 ~100 token 的 Session 摘要

提取内容：
  ✅ 关键事件（"用户说本周要参加考试"）
  ✅ 明确表达的偏好/厌恶
  ✅ 情绪弧线（会话开始积极 → 结束有些沮丧）
  ✅ 未解决的话题（聊到一半被打断的议题）
  ❌ 过滤：问候语、重复内容、闲置寒暄

方法：轻量 LLM 摘要（768M 级别，延迟 < 500ms）
```

**Level 2 — 近期模式归纳**（每周一次批处理）

```
输入：过去 7 天的 Session 摘要列表
目标：跨 Session 发现行为规律和情绪趋势

归纳内容：
  - 话题分布趋势："这周 4 次提到工作，情绪整体偏负"
  - 隐含偏好信号："连续 3 次追问科技新闻 → 科技兴趣偏高"
  - 未满足的诉求："多次询问同类知识但问法不同 → 可能没有获得满意答复"
  - 情绪曲线："周一/二话少偏负，周末积极健谈"

输出：更新 L2 Recent Memory 的「模式摘要」字段
```

**Level 3 — 长期画像蒸馏**（每日 T+1 批处理）

```
输入：全量历史 Session 摘要 + 现有 L3 Offline Profile
目标：提炼/更新稳定的语义级用户特征

处理：
  1. 情节记忆 → 语义记忆转换（见 4.4.2）
  2. 矛盾检测与解消（见 4.4.3）
  3. 重复信号去冗余、合并（见 4.4.4）
  4. 置信度重新评分，低置信 fact 降级归档
  5. 写入 L3 Offline Profile
```

---

#### 4.4.2 情节记忆 → 语义记忆的转换

这是归纳的核心挑战：从具体事件抽象出可复用的通用认知。

**三级抽象层次**：

| 层次 | 示例 | 可用性 |
|------|------|-------|
| 过于具体（无用）| "2026-05-21 说今天天气很好" | 时效性强，无复用价值 |
| **适度抽象（目标）** | "偏好户外话题，喜欢积极自然类内容" | 可长期复用 |
| 过于泛化（无用）| "用户喜欢聊天" | 对所有人都成立，无区分度 |

**转换规则示例**：

```
情节层（存在 L2）：
  「2026-05-20 说在备考研究生，有些焦虑」
  「2026-04-15 说上次面试没过，情绪低落」
  「2026-03-10 说最近工作压力很大」

          ↓  归纳

语义层（写入 L3）：
  known_fact: "学业/职业压力是高敏话题"
  emotional_baseline.stress_triggers: "学业压力", "职业挫折"
  known_fact: "需要情感共情时，不需要直接给建议"
```

**隐含偏好的归纳**（无需用户明确表达）：

```
行为信号：连续 10 次在 21:00-23:00 使用，大多是情感倾诉类
归纳结果：behavioral_patterns.active_hours = "21:00-23:00"
          behavioral_patterns.evening_mode = "情绪陪伴需求高"
```

#### 4.4.3 矛盾检测与解消

用户的偏好和状态会随时间变化，新信号可能与旧 fact 产生矛盾，需要主动检测和处理。

**矛盾类型**：

| 类型 | 示例 | 处理策略 |
|------|------|--------|
| 状态性矛盾 | 之前「喜欢冷笑话」→ 最近说「最近不想笑」 | 短期覆盖：写入 L2，临时降低 L3 fact 权重 |
| 偏好反转 | 之前「喜欢长回复」→ 明确说「说短一点」 | 触发 L3 fact 更新，置信度重置为 0.9 |
| 信息过时 | 之前「在备考」→ 三个月后不再提及 | 时间衰减自动处理（λ 快衰减） |
| 真实矛盾 | 两次明确说了相反的偏好 | 标记为 conflicted，暂不注入 Prompt，等待更多信号 |

**矛盾检测流程**：

```
新抽取的 fact 写入前：
  1. 向量相似度检索现有 facts（cos_sim > 0.85 视为同类）
  2. 语义方向判断（正向/负向情感极性）
  3. 时间戳比较

结论：
  同类 + 同方向            → 合并，提升置信度
  同类 + 反方向 + 时间更新  → 更新旧 fact
  同类 + 反方向 + 时间相近  → 标记 conflicted，不注入 Prompt
```

#### 4.4.4 去冗余与 Fact 合并

同一语义在多次对话中以不同表述出现，需要合并为单一高质量 fact，防止画像臃肿。

**合并示例**：

```
待合并的碎片 facts：
  - "喜欢周杰伦"           (conf: 0.70, 2026-04-10)
  - "爱听周杰伦的歌"       (conf: 0.60, 2026-04-22)
  - "提到了周杰伦新专辑"   (conf: 0.50, 2026-05-08)

合并后：
  - "对周杰伦音乐有持续偏好" (conf: 0.94, 合并自 3 条信号)
```

**合并触发条件**：
- 向量相似度 > 0.88
- 同属同一语义实体或话题
- 来源 Session 不同（同 Session 的重复不视为多信号）

**合并后的置信度公式**：

```
confidence_merged = 1 - ∏(1 - confidence_i)

例：0.70, 0.60, 0.50 三条信号
    merged_conf = 1 - (0.30 × 0.40 × 0.50) = 1 - 0.06 = 0.94
```

---

#### 4.4.5 摘要质量评估

离线摘要/归纳的质量需要可衡量，否则退化无感知。

**离线评估（每周抽样）**：

| 指标 | 方法 | 目标 |
|------|------|------|
| 事件保真率 | 从摘要能否还原关键事件 | > 90% |
| 情绪极性一致性 | 摘要情绪极性 vs 原文人工判断 | Kappa > 0.75 |
| 幻觉率 | 摘要中出现原文没有的事实 | < 3% |
| Fact 精确率 | 归纳出的 fact 是否准确 | > 85% |

**在线信号（间接反映摘要质量）**：

```
负向信号：
  - 用户频繁说"你不记得我之前说的吗" → Session 摘要遗漏重要信息
  - 用户纠正系统的个性化回复         → L3 Profile 归纳出错

正向信号：
  - 用户主动延续上次话题             → L2 近期记忆召回有效
  - 用户对个性化内容给出正向反馈     → L3 Profile 画像准确
```

## 5. 混合融合策略

### 5.1 优先级链

```
信号新鲜度：L1 Session > L2 Recent > L3 Offline Profile

冲突处理：
  - 画像显示"喜欢冷笑话"，但本 Session 用户说"最近不想笑"
    → 以 L1 实时信号为准，临时覆盖 L3 画像
  - 画像显示"喜欢长回复"，但本轮用户说"说短一点"
    → 立即切换，且写入 L2 作为近期信号
```

### 5.2 Prompt 注入结构

```
最终 Prompt 中的记忆部分：

[System 层]
  Base 人设
  ├─ 用户偏好背景（来自 L3 Offline Profile，约 100~200 token）
  │   "这位用户偏好口语化、喜欢冷笑话、最近在备考有些压力"
  └─ 近期记忆摘要（来自 L2 Recent Memory，约 200~300 token）
      "上次聊到要去看演唱会，对最近的工作压力有些倾诉"

[User/Assistant 交替层]
  当前 Session 完整对话轮次（来自 L1 Session Memory）
  按垂域策略决定保留深度（参见 03-推理层/02-模型Prompt笛卡尔组合.md）

[User 层]
  当前 Query
```

### 5.3 冷启动方案

| 阶段 | 状态 | 策略 |
|------|------|------|
| 全新用户 | L1/L2/L3 均为空 | 使用平台默认画像，开启偏好探针 |
| 1~3 次 Session 后 | L2 有少量信号，L3 尚未生成 | 用 L2 Recent Memory 驱动个性化 |
| 7 天后首次离线批处理 | L3 初版画像生成 | 三层融合正式启用 |
| 稳定期 | L3 每日更新 | 完整混合架构运行 |

## 6. 记忆衰减与清理机制

**时间衰减**：

```
Known Facts 置信度公式：
  confidence_t = confidence_0 × e^(-λ × days_elapsed)

  λ = 衰减系数，按 fact 类型不同：
    稳定偏好（humor_style）      : λ = 0.005（慢衰减，半年降一半）
    生活事件（在备考）           : λ = 0.05 （快衰减，两周降一半）
    情绪状态（最近压力大）       : λ = 0.15 （极快衰减，3 天降一半）
```

**主动清理**：
- 置信度低于 0.2 的 fact 自动归档（不再注入 Prompt，但不删除）
- 用户明确否定的 fact（"我不喜欢xxx"）立即标记为 invalid
- L1 Session Memory 在 Session 关闭 2 小时后自动删除

## 7. 难点与亮点

**难点**：

- **一致性维护**：L1 实时信号与 L3 离线画像可能产生冲突，需要清晰的优先级规则和冲突仲裁
- **隐私与合规**：Known Facts 的存储涉及用户个人信息，需做好脱敏、访问控制和用户知情同意
- **抽取准确率**：从对话中提取偏好的 LLM 抽取器本身可能出错，错误 fact 写入画像后会持续影响回复质量，需要置信度过滤 + 定期人工抽查

**亮点**：

- **Online/Offline 互补形成完整时间轴**：Online 捕捉当下（分钟级），Offline 积累历史（月级），两者覆盖了从"现在"到"过去"的完整记忆维度
- **Known Facts 向量检索而非全量注入**：只把和当前 Query 相关的记忆片段注入 Prompt，而非把所有 facts 堆进去——既节省 token，又避免无关记忆干扰当轮回复
- **时间衰减系数按 fact 类型差异化**：情绪状态快衰减（3天降一半），稳定偏好慢衰减（半年降一半），符合人类记忆的实际规律

## 8. 答辩问答预设

> Q：Online Memory 和多轮上下文管理是一回事吗？
> A：不完全是。多轮上下文管理（06-基础能力/01）解决的是"当前 Session 内怎么压缩历史对话注入 Prompt"；Online Memory 的 L2 Recent Memory 解决的是"Session 结束后，有价值的信息怎么跨 Session 保留"。前者是 Prompt 工程问题，后者是持久化存储问题。

> Q：为什么不直接用 RAG，把所有历史对话存进向量库？
> A：有三个问题。一是历史对话原文噪声极大（大量寒暄、重复），直接向量化检索精度很低；二是对话轮数多时向量库检索延迟会影响 P50 延迟；三是对话文本的语义分散，用户问"今天天气"检索不到"上次说要去看演唱会"这条记忆。Offline Profiling 的做法是先用 LLM 提取结构化 facts，再对 facts 做向量检索，精度和效率都更可控。

> Q：Known Facts 抽错了怎么办，错误信息会一直影响用户体验？
> A：三道防线。第一，置信度门槛：低置信 facts 不注入 Prompt，只存档；第二，时间衰减：错误 fact 置信度会随时间自然降低；第三，用户否定信号：用户一旦表达"我不是这样的"，立即将该 fact 标记 invalid 并触发同类 facts 回扫。此外，每周人工抽查批处理结果，发现系统性抽取偏差就调整 Prompt。

> Q：Offline Profile 是 T+1 更新，用户今天说的话明天才能反映到画像，这个延迟可以接受吗？
> A：可以，因为 Offline Profile 对应的是"稳定偏好"和"长期特征"，这类信息本身就不需要实时性。今天刚说的临时情绪（"今天心情不好"）靠 L1/L2 Online Memory 实时捕捉，而"这个人喜欢冷笑话"这类特征积累几天再更新也不影响体验。分层设计的好处就是各层对实时性的要求不同，不用全部实时化。

> Q：记忆系统会不会带来隐私风险？
> A：会，这是真实存在的风险，需要认真对待。Known Facts 涉及用户的个人信息和情绪状态，至少要做到：明确的用户知情授权（告知会记忆哪些信息）、数据分级存储（高敏感 fact 加密存储）、用户可查看和删除自己的画像（Right to Erasure）。这不只是合规要求，也是产品信任建设的一部分。
