### 3.6 监控 & 可观测性

**为什么必须有**：闲聊智能体链路长、模块多，没有全链路监控，出问题时故障定位要几个小时甚至几天。

**全链路 Tracing**：

```
每个请求生成唯一 trace_id，贯穿所有模块：

接入层   → [trace_id: abc123, ts: T0]
改写模块 → [trace_id: abc123, latency: 15ms, rewrite: true]
分类模块 → [trace_id: abc123, latency: 22ms, label: chat, conf: 0.91]
AB 分桶  → [trace_id: abc123, group: exp_A, combo: M1+P2]
LLM 推理 → [trace_id: abc123, latency: 820ms, tokens: 312]
后处理   → [trace_id: abc123, latency: 8ms, safe: true]
下发     → [trace_id: abc123, total_latency: 910ms]
```

**监控看板核心指标**：

| 指标 | 告警阈值 | 告警级别 |
|------|----------|----------|
| 请求成功率 | < 99% | P1 |
| P99 端到端延迟 | > 3s | P1 |
| 首 Token 延迟 P50 | > 500ms | P2 |
| 模型调用失败率 | > 2% | P1 |
| 安全拦截率突变 | 环比 > 3x | P2 |
| 单日 token 消耗 | > 预算 80% | P2 |
| AB 实验组指标显著差异 | p-value < 0.05 | 通知 |
