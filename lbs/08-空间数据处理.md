# 08 空间数据处理

## 总览：空间数据处理是 LBS 的数据底座

空间数据处理是对点、线、面等地理数据进行清洗、转换、计算、融合和分析。POI、路网、轨迹、围栏、行政区、商圈、地图图层都依赖空间数据处理。

对 0 基础后端来说，可以先把空间数据理解成“带几何形状的业务数据”。普通业务表只有字段，空间数据除了字段，还有坐标、形状、坐标系、拓扑关系和空间索引。

答辩中这一节常考：

- 点、线、面分别是什么。
- 坐标系和投影为什么重要。
- 常见空间计算有哪些。
- 如何判断点是否在多边形内。
- 空间数据质量问题如何处理。
- 批处理和实时处理有什么区别。

## 分解一：空间数据类型

### Point 点

点表示一个位置。

常见场景：

- 用户当前位置。
- 门店。
- 司机。
- 骑手。
- 站点。
- 设备。

表示方式：

```json
{
  "type": "Point",
  "coordinates": [116.3, 39.9]
}
```

注意 GeoJSON 中通常是 `[longitude, latitude]`，也就是经度在前。

### LineString 线

线由多个点组成。

常见场景：

- 道路。
- 路线。
- 轨迹。
- 公交线路。

表示方式：

```json
{
  "type": "LineString",
  "coordinates": [
    [116.3, 39.9],
    [116.31, 39.91],
    [116.32, 39.92]
  ]
}
```

线可以计算长度、是否与区域相交、是否偏离路线。

### Polygon 面

面是封闭区域。

常见场景：

- 行政区。
- 商圈。
- 配送范围。
- 小区边界。
- 禁行区。

表示方式：

```json
{
  "type": "Polygon",
  "coordinates": [
    [
      [116.3, 39.9],
      [116.4, 39.9],
      [116.4, 40.0],
      [116.3, 40.0],
      [116.3, 39.9]
    ]
  ]
}
```

面要求首尾闭合，复杂面可能包含洞。

## 分解二：坐标系和投影

空间数据计算必须关注坐标系。

常见概念：

- 地理坐标系：经纬度，单位是度。
- 投影坐标系：平面坐标，单位常是米。
- Web Mercator：互联网地图常用投影。

为什么重要：

- 经纬度不能直接做精确面积计算。
- 不同纬度下 1 度经度对应距离不同。
- 缓冲区、面积、长度计算最好在合适投影下完成。
- 多源数据坐标系不同会导致图层偏移。

后端原则：

- 存储坐标系要统一。
- 对外接口要声明坐标系。
- 空间计算前确认坐标系。
- 面积、缓冲区等计算要选合适投影。

## 分解三：常见空间计算

### 距离

包括：

- 点到点距离。
- 点到线距离。
- 点到面边界距离。

场景：

- 附近搜索。
- 到达判断。
- 地图匹配候选召回。

### 包含

判断一个对象是否在另一个对象内部。

场景：

- 点是否在配送区内。
- 用户是否在行政区内。
- 车辆是否在禁行区内。

### 相交

判断两个对象是否有交集。

场景：

- 轨迹是否穿过风险区域。
- 路线是否经过施工区。
- 两个业务区域是否重叠。

### 缓冲区

围绕点、线或面生成一定距离范围。

场景：

- 门店 100 米到店范围。
- 路线两侧 50 米范围。
- 道路施工影响范围。

### 合并和裁剪

场景：

- 多个配送区合并。
- 按行政区裁剪轨迹。
- 生成城市级统计区域。

## 分解四：空间数据格式

常见格式：

- GeoJSON：易读，前后端交互常用。
- WKT：文本表达，例如 `POINT(116.3 39.9)`。
- WKB：二进制表达，适合存储和传输。
- Shapefile：传统 GIS 数据格式。
- MVT：Mapbox Vector Tile，矢量瓦片格式。

后端答辩中最常见的是 GeoJSON、WKT 和空间数据库字段。

## 分解五：空间数据质量问题

### 点数据问题

- 经纬度为空。
- 经纬度顺序写反。
- 坐标超出合法范围。
- 点落在异常区域。
- 重复点。
- 坐标系不一致。

### 线数据问题

- 轨迹跳点。
- 道路断裂。
- 线段重复。
- 方向错误。
- 线自交。

### 面数据问题

- 多边形不闭合。
- 自交。
- 面积异常。
- 边界重叠。
- 相邻面之间有缝隙。
- 孔洞错误。

质量治理方法：

- 入库前规则校验。
- 使用几何库修复。
- 重复数据合并。
- 可视化审核。
- 异常指标监控。
- 数据版本管理。

## 分解六：批处理和实时处理

### 离线批处理

适合：

- POI 清洗。
- 行政区边界更新。
- 路网构建。
- 历史轨迹分析。
- 热力图统计。
- 围栏批量生成。

特点：

- 数据量大。
- 时延要求低。
- 可以使用复杂算法。
- 结果通常写入数据库或数据仓库。

### 实时处理

适合：

- 实时位置上报。
- 围栏命中。
- 司机位置同步。
- 轨迹异常检测。
- 实时路况计算。

特点：

- 时延要求高。
- 需要空间索引和缓存。
- 需要处理乱序、重复和延迟数据。

实际系统经常是离线构建基础数据，实时服务基于这些数据快速判断。

## 后端开发视角：空间数据怎么落库和计算

### 数据库存储

常见选择：

- PostgreSQL + PostGIS。
- MySQL Spatial。
- Elasticsearch geo_point / geo_shape。
- Redis GEO。
- 大数据平台中的空间扩展。

### 表设计示例

```text
delivery_area
- id
- name
- city_code
- geometry
- coord_type
- status
- version
- updated_at
```

### 查询思路

判断点是否在配送区内：

1. 校验点坐标。
2. 用空间索引召回候选配送区。
3. 对候选区做点面包含判断。
4. 返回命中结果和围栏版本。

### 工程注意点

- 不要对全表逐个做几何计算。
- 先用空间索引粗筛。
- 复杂几何对象可以简化。
- 大对象要注意存储和网络传输成本。
- 结果需要可视化排查。

## 答辩高频问题

### 问：点、线、面在 LBS 中分别对应什么？

答题思路：

- 点：用户、门店、车辆。
- 线：道路、路线、轨迹。
- 面：行政区、商圈、围栏、配送区。

### 问：为什么经纬度不能直接算面积？

答题思路：

- 经纬度是角度，不是米。
- 不同纬度下距离比例不同。
- 面积和缓冲区计算需要合适投影。

### 问：如何高效判断点是否在多边形内？

答题思路：

- 先用空间索引或外接矩形粗筛候选面。
- 再做精确点面包含判断。
- 大量围栏要结合缓存、分区和索引。

## 本节总结：答辩突击记忆清单

- 空间数据是带几何形状的业务数据。
- LBS 主要处理点、线、面。
- 坐标系和投影会影响距离、面积和展示。
- 常见空间计算包括距离、包含、相交、缓冲区、裁剪、合并。
- 空间数据质量问题包括坐标错、线断裂、面不闭合、自交和重复。
- 后端做空间计算时要先索引粗筛，再精确计算。

如果时间有限，重点准备“如何判断用户地址是否在配送范围内”，这个问题能覆盖点、面、空间索引、坐标系和工程性能。
