# 07 底图渲染与地图展示

## 总览：地图展示不是把点画上去这么简单

底图渲染与地图展示负责把道路、建筑、水系、绿地、行政区、POI、路况和业务图层展示给用户。对后端开发来说，这一节容易被误以为是前端或客户端内容，但 LBS 中台后端同样需要理解地图展示的数据组织、图层服务、瓦片、聚合和性能优化。

0 基础后端要抓住一句话：地图展示的本质是“按视野、缩放层级和业务优先级，把空间数据高效地组织并返回给客户端”。

答辩中常见问题：

- 栅格瓦片和矢量瓦片有什么区别。
- 如何在地图上展示 10 万个点。
- 图层为什么要按缩放层级控制。
- 标注重叠怎么处理。
- 业务点位和底图坐标不一致怎么排查。

## 分解一：底图和业务图层

### 底图

底图是地图的基础背景。

包括：

- 道路。
- 建筑。
- 水系。
- 绿地。
- 行政区边界。
- 地铁线路。
- 基础 POI。
- 地形或影像。

底图强调通用地理信息表达，通常由地图厂商或底图服务提供。

### 业务图层

业务图层是业务系统叠加在底图上的空间数据。

例如：

- 门店点位。
- 骑手位置。
- 司机位置。
- 订单轨迹。
- 配送范围。
- 仓库和站点。
- 热力图。
- 运营区域。

业务图层更依赖后端服务，因为它要按业务权限、状态、区域、视野和缩放层级动态返回。

## 分解二：地图瓦片

互联网地图通常按瓦片加载。

瓦片可以理解为地图被切成很多小块，客户端只加载当前屏幕需要的小块。

常见瓦片坐标：

```text
z：缩放层级
x：横向瓦片编号
y：纵向瓦片编号
```

### 栅格瓦片

栅格瓦片是图片。

优点：

- 客户端显示简单。
- 兼容性好。
- 服务端渲染后效果一致。

缺点：

- 样式不灵活。
- 交互能力弱。
- 高清屏和多主题维护成本高。

### 矢量瓦片

矢量瓦片返回点、线、面等矢量数据，由客户端渲染。

优点：

- 样式灵活。
- 支持旋转、倾斜、动态主题。
- 交互能力强。
- 数据量可控。

缺点：

- 客户端渲染复杂。
- 对样式系统要求高。
- 需要处理标注避让和性能。

后端需要理解瓦片，是因为业务图层也可以按瓦片组织。例如请求某个 `z/x/y` 瓦片内的门店、车辆或热力数据。

## 分解三：图层管理

地图不是一张图，而是多个图层叠加。

常见顺序：

1. 背景底色。
2. 水系、绿地、建筑。
3. 道路。
4. 道路文字。
5. POI 图标和名称。
6. 路况。
7. 业务点位。
8. 轨迹、围栏、热力图。
9. 弹窗和选中态。

后端提供业务图层时要考虑：

- 当前缩放层级是否应该显示。
- 当前用户是否有权限看。
- 是否只返回当前视野内数据。
- 是否要聚合。
- 是否需要按状态分层，例如在线司机、忙碌司机、离线司机。

## 分解四：缩放层级和数据密度

地图缩放层级越低，看到的范围越大，不可能展示全部细节。

例如：

- 全国视角：只展示城市级统计。
- 城市视角：展示区域热力或聚合点。
- 街区视角：展示具体门店和道路。
- 楼宇视角：展示入口、楼层、具体点位。

后端常见策略：

- 低层级返回聚合结果。
- 中层级返回网格统计。
- 高层级返回具体点位。
- 超大视野限制返回数量。
- 按业务优先级抽稀。

这就是为什么展示大量点位时不能一次性全返回。

## 分解五：海量点展示

答辩中经常问“如何在地图上展示 10 万个点”。

回答思路：

### 视野裁剪

只返回当前地图视野内的数据。

请求参数一般包括：

```json
{
  "minLng": 116.1,
  "minLat": 39.7,
  "maxLng": 116.6,
  "maxLat": 40.1,
  "zoom": 12
}
```

### 空间索引

使用 Geohash、S2、R-Tree 等索引快速查询视野内对象。

### 聚合

低缩放层级把多个点合成一个聚合点。

例如：

```text
当前区域内 235 个门店 -> 展示一个数字气泡
```

### 抽稀

如果点太密，可以按网格、热度、优先级保留部分点。

### 分片加载

按瓦片或网格加载，避免一次请求太大。

### 缓存

静态点位或低频变化数据可以缓存，减少数据库压力。

## 分解六：标注避让

地图上的文字和图标很容易重叠。标注避让用于决定哪些标注显示、显示在哪里、哪些隐藏。

影响因素：

- 标注优先级。
- 缩放层级。
- 屏幕空间。
- 是否被用户选中。
- POI 热度。
- 业务重要性。

后端不一定负责最终避让，但需要提供：

- 图层优先级。
- 点位权重。
- 类目等级。
- 展示标签。
- 选中态和高亮态数据。

## 后端开发视角：地图图层服务怎么设计

### 典型接口

```json
{
  "viewport": {
    "minLng": 116.1,
    "minLat": 39.7,
    "maxLng": 116.6,
    "maxLat": 40.1
  },
  "zoom": 13,
  "layers": ["store", "rider", "delivery_area"],
  "filters": {
    "status": "open"
  }
}
```

### 返回结果

```json
{
  "layer": "store",
  "mode": "cluster",
  "features": [
    {
      "id": "c1",
      "type": "cluster",
      "longitude": 116.3,
      "latitude": 39.9,
      "count": 32
    }
  ]
}
```

### 后端关注点

- 视野参数校验。
- zoom 与返回粒度映射。
- 空间索引查询。
- 聚合算法。
- 缓存。
- 权限控制。
- 坐标系转换。
- 返回数量限制。

## 常见问题和排查

### 点位整体偏移

优先排查：

- 坐标系是否一致。
- 经纬度是否写反。
- 前端 SDK 默认坐标系。
- 后端是否重复转换。

### 地图很卡

排查：

- 是否一次返回太多点。
- 是否没有视野裁剪。
- 是否没有聚合。
- 轨迹线点数是否太多。
- 客户端渲染是否使用合适方式。

### 点位重叠严重

排查：

- 是否需要聚合。
- 是否需要按优先级展示。
- 是否需要标注避让。
- 是否需要在低 zoom 隐藏部分图层。

## 答辩高频问题

### 问：如何展示 10 万个门店点位？

答题思路：

- 不一次性返回。
- 按视野和 zoom 查询。
- 使用空间索引。
- 低层级聚合，高层级展示明细。
- 做缓存和返回数量限制。

### 问：矢量瓦片和栅格瓦片有什么区别？

答题思路：

- 栅格瓦片是图片，展示简单但交互和样式弱。
- 矢量瓦片是数据，客户端渲染，样式灵活、交互强，但复杂度高。

### 问：业务图层和底图错位怎么排查？

答题思路：

- 检查坐标系。
- 检查经纬度顺序。
- 检查地图 SDK 使用坐标。
- 检查数据转换和缓存版本。

## 本节总结：答辩突击记忆清单

- 地图展示是底图和业务图层的组合。
- 瓦片解决地图按需加载问题。
- 业务图层后端要按视野、zoom、权限和状态返回数据。
- 海量点展示要用视野裁剪、空间索引、聚合、抽稀、缓存。
- 点位偏移优先查坐标系和经纬度顺序。
- 地图性能问题通常来自返回数据量过大或渲染粒度不合理。

如果只准备一个问题，就准备“地图上展示 10 万个点如何设计”，这是后端答辩非常高频且容易体现工程思维的问题。
