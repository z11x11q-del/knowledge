﻿# 04 路线规划

## 总览：路线规划是在路网里求最优路径

路线规划是根据起点、终点、交通方式和业务约束，在道路网络中计算一条或多条可行路径。它是导航、ETA、配送、网约车、物流和本地生活履约的基础能力。

0 基础后端可以先这样理解：路线规划不是在地图上把两个点连成一条直线，而是在一张巨大的道路图中找一条综合成本最优的路径。

答辩中经常会问：

- 路网怎么建模。
- 为什么最短路不一定是最佳路线。
- Dijkstra 和 A* 的基本思想。
- ETA 为什么会不准。
- 实时路况如何影响路线。
- 驾车、步行、骑行、货运路线有什么差异。

## 分解一：路网图模型

路线规划的基础是路网。路网可以抽象成图：

- 节点：道路交叉口、道路端点、匝道口、出入口。
- 边：两个节点之间的道路片段。
- 权重：通过这条边的成本。

### 道路边的常见属性

```text
edge_id
from_node
to_node
geometry
length
road_level
speed_limit
direction
toll_flag
turn_restrictions
vehicle_restrictions
historical_speed
real_time_speed
```

需要理解：

- 单行线会影响方向。
- 禁止左转、禁止掉头会影响转向。
- 高速、主路、辅路的通行成本不同。
- 货车可能有限高、限重、限行。
- 路况会让同一条路在不同时间成本不同。

## 分解二：路径成本不是只有距离

路线规划的本质是最小化成本，但成本不一定是距离。

常见成本：

- 距离最短。
- 时间最快。
- 收费最少。
- 红绿灯少。
- 拥堵少。
- 高速优先。
- 避开高速。
- 安全性高。
- 符合车辆限制。

例如：

- 用户开车时，10 公里快速路可能比 6 公里市区小路更快。
- 货车路线不能走限高道路。
- 骑行路线不能走高速。
- 配送路线可能更关注准时和安全。

答辩回答可以说：路线规划通常是多因素加权，不是简单最短路径。

## 分解三：常见路径算法

### Dijkstra

Dijkstra 用于求非负权重图中的最短路径。

核心思想：

- 从起点出发。
- 每次选择当前已知成本最小的节点扩展。
- 不断更新到其他节点的最小成本。
- 直到找到终点。

优点：

- 思路清晰。
- 结果稳定。
- 适合基础最短路。

缺点：

- 在大规模路网中可能扩展很多无关节点。

### A*

A* 在 Dijkstra 基础上加入启发式估计。

核心公式：

```text
f(n) = g(n) + h(n)
```

含义：

- `g(n)`：从起点到当前节点的真实成本。
- `h(n)`：从当前节点到终点的估计成本。
- `f(n)`：总评估成本。

如果 `h(n)` 使用到终点的直线距离估计，算法会更倾向朝终点方向搜索，从而减少搜索范围。

### 双向搜索

双向搜索从起点和终点同时搜索，中间相遇后得到路径。它适合大规模点到点路径查询。

### 分层路网

分层路网把道路按等级组织。长距离路线先走高等级道路，局部区域再走低等级道路。

意义：

- 提升长距离规划性能。
- 更符合人类出行习惯。
- 需要复杂预处理。

答辩不需要手写这些算法，但要能说清它们解决的问题和基本思想。

## 分解四：起终点吸附

用户给出的起点和终点通常是经纬度，但路网计算需要把它们关联到道路或入口点。

这个过程叫起终点吸附。

常见问题：

- 点在建筑中心，不在道路上。
- 点在高架和地面重叠区域。
- 点在小区内部道路。
- 点在河道、绿地或不可达区域。
- 起点和终点坐标系错误。

吸附策略：

- 查找附近可通行道路。
- 根据交通方式过滤道路。
- 考虑道路方向。
- 考虑入口点和停车点。
- 对低精度定位扩大候选范围。

起终点吸附错误会直接导致路线看起来绕路或不可达。

## 分解五：实时路况与 ETA

ETA 是预计到达时间，通常比路线本身更受业务关注。

ETA 影响因素：

- 路段长度。
- 实时速度。
- 历史分时速度。
- 拥堵程度。
- 红绿灯等待。
- 转向成本。
- 收费站和匝道。
- 上车、停车、取货、送达等待。

路况数据来源：

- 用户和车辆轨迹。
- 导航上报。
- 交通事件。
- 传感器。
- 历史模型。

ETA 不准时排查方向：

- 路况是否及时。
- 速度模型是否适合当前时间段。
- 是否有临时封路或事故。
- 起终点吸附是否错误。
- 是否漏算等待时间。
- 交通方式是否识别正确。

## 分解六：多交通方式差异

### 驾车

关注：

- 单行线。
- 限行。
- 高速和收费。
- 转向限制。
- 实时拥堵。
- 车牌规则。

### 步行

关注：

- 人行道。
- 过街天桥。
- 地下通道。
- 园区小路。
- 安全性。

### 骑行

关注：

- 非机动车道。
- 禁行道路。
- 桥梁和隧道。
- 坡度。
- 骑行安全。

### 公交

关注：

- 站点。
- 线路。
- 班次。
- 发车间隔。
- 换乘。
- 步行接驳。

### 货运

关注：

- 限高。
- 限重。
- 限宽。
- 禁行区域。
- 危险品限制。
- 货车通行证。

答辩时可以强调：不同交通方式不是换个速度参数，而是路网、规则和成本模型都不同。

## 后端开发视角：路线规划服务怎么设计

### 请求参数

```json
{
  "origin": {
    "longitude": 116.30,
    "latitude": 39.90
  },
  "destination": {
    "longitude": 116.40,
    "latitude": 39.95
  },
  "coordType": "GCJ02",
  "mode": "driving",
  "strategy": "fastest",
  "avoidTolls": false,
  "plateNumber": "京A12345"
}
```

### 响应结果

```json
{
  "distance": 12500,
  "duration": 1800,
  "routes": [
    {
      "routeId": "r1",
      "strategy": "fastest",
      "polyline": "...",
      "steps": [],
      "tolls": 0,
      "trafficLights": 12
    }
  ]
}
```

### 后端关注点

- 坐标系校验。
- 起终点吸附。
- 路网版本。
- 路况数据接入。
- 多策略路线。
- 超时和降级。
- 结果缓存。
- 日志和可解释性。

### 降级策略

- 实时路况不可用时使用历史速度。
- 精细路线失败时返回静态路线。
- 多路线失败时返回单路线。
- 长距离规划超时时降低策略复杂度。

## 答辩高频问题

### 问：为什么最短路线不一定是最快路线？

答题思路：

- 路线成本可以是距离，也可以是时间。
- 快速路虽然更远，但速度更快、红绿灯更少。
- 实时拥堵和转向成本会影响耗时。

### 问：A* 相比 Dijkstra 有什么优势？

答题思路：

- Dijkstra 按已知最小成本扩展，可能搜索很多无关区域。
- A* 加入到终点的启发式估计，更倾向朝终点方向搜索。
- 在路网中可以减少搜索范围，提高性能。

### 问：ETA 不准怎么排查？

答题思路：

- 检查起终点吸附。
- 检查路况和历史速度。
- 检查交通方式。
- 检查是否有封路、施工、限行。
- 检查红绿灯、等待时间和业务附加时间。

## 本节总结：答辩突击记忆清单

- 路线规划是在路网图中求综合成本最优路径。
- 路网由节点和边组成，边有方向、长度、速度、限制等属性。
- Dijkstra 求最短路，A* 加启发式减少搜索范围。
- 路线成本不只是距离，也可能是时间、收费、拥堵、安全和业务偏好。
- ETA 是路线规划中非常关键的业务指标。
- 起终点吸附错误会导致路线绕路或不可达。
- 不同交通方式对应不同路网规则。

如果只准备一个案例，可以讲“网约车从乘客位置到目的地如何规划路线并计算 ETA”，这个案例能覆盖路网、吸附、路况、算法和业务约束。
