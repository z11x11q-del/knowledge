# 05 导航能力

## 总览：导航是路线规划之后的实时引导系统

导航不是路线规划的另一个名字。路线规划回答“从 A 到 B 应该怎么走”，导航回答“用户现在走到哪里了、下一步该怎么提示、是否偏航、是否需要重算、是否到达”。

对 0 基础后端来说，可以把导航理解成一个实时状态系统：服务端先给出路线，客户端持续上传或使用定位，系统不断判断用户在路线上的位置，并根据状态触发播报、重算和到达事件。

答辩中导航常被用来区分候选人是否理解 LBS 的实时性：

- 导航和路线规划有什么区别。
- 为什么需要地图匹配。
- 偏航怎么判断。
- 语音播报为什么不是固定距离触发。
- 终点到达为什么容易出问题。

## 分解一：导航的完整链路

一次导航大致包括以下步骤：

1. 用户选择起点、终点和交通方式。
2. 路线规划服务返回路线、路段、转向动作、ETA。
3. 客户端开始导航，持续获取定位。
4. 定位点经过坐标转换、精度判断和地图匹配。
5. 导航状态机判断用户所在路线段。
6. 根据距离、速度、道路复杂度触发播报。
7. 如果发现偏航，触发路线重算。
8. 接近终点时判断是否到达。

这里面服务端和客户端会分工：

- 服务端负责路线规划、ETA、路况、重算、部分引导信息。
- 客户端负责定位采集、地图渲染、播报、本地状态更新。
- 一些能力可以端云协同，例如偏航初判在端上，确认和重算在服务端。

## 分解二：导航状态机

导航过程可以抽象成状态机。

常见状态：

- 未开始。
- 起步中。
- 正常巡航。
- 临近转向。
- 通过路口。
- 偏航疑似。
- 偏航确认。
- 路线重算中。
- 接近终点。
- 已到达。

状态机的作用是避免系统只靠单个定位点做判断。

例如：

- 单点偏离路线不一定是真偏航，可能是 GPS 漂移。
- 单点接近终点不一定到达，可能隔着围墙或在高架上。
- 临近复杂路口时需要提前播报，而不是等到路口才提示。

后端在设计导航事件服务时，需要记录用户当前路线、当前路段、最近定位点、历史状态和重算次数。

## 分解三：地图匹配在导航中的作用

导航不能直接相信原始 GPS 点。GPS 点会漂移，尤其在高楼、隧道、高架和城市密集道路中。

地图匹配要解决：

- 当前定位点更可能在哪条路上。
- 用户在规划路线的哪一段。
- 是否已经通过某个路口。
- 是否偏离规划路线。

匹配时通常参考：

- 定位点到道路的距离。
- 行驶方向与道路方向是否一致。
- 当前速度是否合理。
- 前后点是否连续。
- 当前道路是否在规划路线附近。

导航中的地图匹配比离线轨迹匹配更强调实时性和稳定性。它不能为了全局最优等很久，也不能在主路和辅路之间频繁跳动。

## 分解四：偏航判断

偏航是指用户实际行驶路径偏离了规划路线。

偏航判断不能只看“当前点到路线距离大于阈值”，因为定位漂移会造成误判。

常见判断因素：

- 连续多个定位点偏离路线。
- 偏离距离超过阈值。
- 行驶方向与规划路线方向明显不一致。
- 当前匹配道路不在规划路线候选范围内。
- 用户错过了应该转向的路口。
- 偏离持续时间超过阈值。

偏航判断通常分两步：

1. 疑似偏航：发现当前状态异常。
2. 确认偏航：连续多点、多特征确认后触发重算。

重算也要限频。如果用户在信号差区域，频繁重算会让体验更差。

## 分解五：语音播报策略

语音播报不是固定距离触发。播报要给用户足够反应时间。

影响播报时机的因素：

- 当前速度。
- 距离下一个动作的距离。
- 道路等级。
- 路口复杂度。
- 是否需要变道。
- 是否连续转向。
- 是否高速出口或匝道。

例如：

- 高速上 1 公里外就可能需要提示。
- 城市低速道路 200 米提示可能足够。
- 连续路口要提前告知“前方右转后立即左转”。

常见播报层级：

- 远距离预告。
- 中距离确认。
- 近距离执行。
- 通过路口后确认。

后端可能会在路线规划结果中生成引导动作和播报点，客户端根据实时速度和位置动态触发。

## 分解六：终点到达判断

终点到达看似简单，实际很容易出问题。

原因：

- 终点坐标可能是建筑中心点，不是入口。
- 商场、医院、园区可能有多个入口。
- 用户在高架上接近终点，但不能下车。
- 小区内部道路和外部道路不连通。
- 停车场入口和步行入口不同。

到达判断常用因素：

- 距离终点是否足够近。
- 是否在可达道路上。
- 是否经过最后一个导航动作。
- 速度是否降低或停车。
- 是否进入终点围栏。
- 是否到达入口点而不是中心点。

对网约车来说，上车点、下车点、停车点比 POI 中心点更重要。对配送来说，楼栋和门口可能比小区中心点更重要。

## 后端开发视角：导航相关服务怎么设计

### 路线结果结构

导航依赖的路线结果通常包含：

```json
{
  "routeId": "r123",
  "distance": 12500,
  "duration": 1800,
  "polyline": "...",
  "steps": [
    {
      "instruction": "前方右转",
      "distance": 300,
      "roadName": "中关村大街",
      "action": "turn_right"
    }
  ],
  "traffic": [],
  "destinationGuide": {}
}
```

### 导航事件

后端可能需要处理的导航事件：

- 开始导航。
- 位置更新。
- 偏航。
- 路线重算。
- 通过关键路口。
- 到达终点。
- 结束导航。

事件字段示例：

```text
user_id
route_id
longitude
latitude
speed
direction
accuracy
timestamp
matched_road_id
nav_state
```

### 日志和可观测性

导航问题排查很依赖日志。

需要记录：

- 原始定位点。
- 匹配道路。
- 当前路线段。
- 偏航判断原因。
- 重算次数。
- ETA 变化。
- 播报触发点。

没有这些日志，线上用户反馈“导航乱跳”很难定位。

## 常见问题和排查

### 导航频繁偏航

排查：

- 定位精度是否差。
- 地图匹配是否跳路。
- 偏航阈值是否过小。
- 路网是否过旧。
- 高架和地面道路是否混淆。

### 播报太晚

排查：

- 是否考虑速度。
- 路口复杂度是否识别。
- 引导动作是否生成准确。
- 客户端定位延迟是否过大。

### 终点到达不准确

排查：

- 终点是否用中心点。
- 是否有入口点。
- 是否隔着围墙、河流、高架。
- 是否需要停车点或下车点。

## 答辩高频问题

### 问：导航和路线规划的区别是什么？

答题思路：

- 路线规划是计算从起点到终点的路径。
- 导航是在行进过程中基于定位、地图匹配、状态机和播报持续引导。
- 导航还包含偏航重算和到达判断。

### 问：偏航如何判断？

答题思路：

- 不能只看单点距离。
- 要结合连续定位点、偏离距离、方向、匹配道路、是否错过路口。
- 需要疑似偏航和确认偏航，避免 GPS 漂移导致误判。

### 问：为什么终点体验经常不好？

答题思路：

- POI 中心点不一定可达。
- 大型场所有多个入口。
- 车辆和步行可达点不同。
- 需要入口点、停车点、下车点和最后一公里引导。

## 本节总结：答辩突击记忆清单

- 导航是路线规划之后的实时引导系统。
- 导航依赖定位、地图匹配、状态机、播报、偏航重算和到达判断。
- 偏航不能只靠单点距离判断。
- 播报策略要考虑速度、距离和道路复杂度。
- 终点到达要关注入口点和可达性。
- 导航问题排查要记录原始定位、匹配道路、路线段、偏航原因和重算日志。

如果时间有限，重点准备“用户导航时 GPS 漂移导致频繁偏航，怎么优化”这个问题，它能覆盖定位、匹配、状态机和业务体验。
