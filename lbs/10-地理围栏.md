# 10 地理围栏

## 总览：地理围栏是把业务规则画到地图上

地理围栏是围绕点、线或面定义一个区域，并判断用户、车辆、骑手、设备是否进入、离开、停留或经过这个区域。它是 LBS 中非常常见的业务能力。

0 基础后端可以这样理解：地理围栏就是“空间边界 + 位置流 + 状态机 + 事件通知”。

答辩中常见问题：

- 圆形围栏和多边形围栏有什么区别。
- 如何判断点是否在多边形内。
- 为什么围栏判断不能只看单个定位点。
- 定位漂移导致频繁进出围栏怎么办。
- 大量围栏如何高性能判断。

## 分解一：围栏类型

### 圆形围栏

由中心点和半径定义。

适合：

- 门店附近 100 米到店。
- 上车点到达。
- 设备附近告警。

优点：

- 计算简单。
- 存储简单。
- 适合点周边场景。

缺点：

- 表达真实边界能力弱。
- 容易覆盖不可达区域。

### 多边形围栏

由多个边界点组成。

适合：

- 配送范围。
- 商圈。
- 小区。
- 园区。
- 禁行区。

优点：

- 能表达复杂边界。
- 更贴近真实业务区域。

缺点：

- 几何计算复杂。
- 需要处理自交、不闭合、边界误差。

### 行政区围栏

使用省、市、区县、街道边界作为围栏。

适合：

- 城市运营范围。
- 区域统计。
- 区域权限。
- 风控城市判断。

### 线缓冲区围栏

围绕路线、道路、轨迹生成一定宽度区域。

适合：

- 判断车辆是否沿路线行驶。
- 判断轨迹是否经过施工路段。
- 监控路线偏离。

## 分解二：围栏事件

围栏不是只返回 true 或 false。业务通常需要事件。

常见事件：

- Enter：进入围栏。
- Exit：离开围栏。
- Stay：停留达到一定时间。
- Pass：经过围栏。

例如骑手到店：

1. 骑手在门店围栏外。
2. 定位点逐渐接近。
3. 连续多个点进入围栏。
4. 停留超过 30 秒。
5. 触发到店事件。

如果只看单点进入，GPS 漂移会造成大量误触发。

## 分解三：点面判断

地理围栏的基础计算是空间关系判断。

常见判断：

- 点是否在圆内。
- 点是否在多边形内。
- 点到边界的距离。
- 线是否穿过多边形。
- 面和面是否相交。

点在多边形内常用算法包括射线法、环绕数法等。答辩中不一定要手写，但要知道它是精确几何计算。

工程上要注意：

- 先用空间索引召回候选围栏。
- 再对候选做精确点面判断。
- 边界点要定义清楚算内还是算外。
- 坐标系必须一致。

## 分解四：定位抖动和降噪

围栏最大的实际问题是定位抖动。

边界附近定位点可能这样变化：

```text
外 -> 内 -> 外 -> 内 -> 外
```

如果每次都触发 Enter/Exit，业务会被事件打爆。

常见降噪策略：

- 连续命中：连续 N 个点在围栏内才进入。
- 停留时间：进入后停留超过阈值才触发。
- 缓冲区：设置内外缓冲带。
- 冷却时间：短时间内不重复触发同类事件。
- 精度过滤：精度差的点不参与关键判断。
- 状态机：外部、疑似进入、内部、疑似离开。

### 缓冲区思路

可以设置两个边界：

- 进入边界：稍微向内收缩，避免误进。
- 离开边界：稍微向外扩张，避免误出。

这样可以减少边界抖动。

## 分解五：大规模围栏判断

如果只有几十个围栏，可以逐个判断。如果有几十万围栏，就必须使用空间索引。

常见流程：

1. 围栏入库时建立空间索引。
2. 定位点上报时，根据点坐标召回候选围栏。
3. 对候选围栏做精确判断。
4. 读取对象上一次围栏状态。
5. 状态机生成 Enter/Exit/Stay 事件。
6. 事件去重、限流后发给业务系统。

实时系统中常用组件：

- Redis 存对象当前围栏状态。
- Kafka 或消息队列传递位置流和围栏事件。
- 空间数据库或内存索引做候选召回。
- Flink 等流处理做实时判断。

```json
{
  "objectId": "rider_123",

  "confidence": 0.94

```

### 关键设计

- 围栏版本管理。
- 空间索引。
- 状态缓存。
- 事件幂等。
- 去重和冷却。
- 异步通知。
- 监控和回放。

## 典型业务场景

- 外卖骑手到店。
- 用户到店核销。
- 司机到达上车点。
- 物流车辆进出仓库。
- 判断用户地址是否在配送范围。
- 车辆进入禁停区告警。
- 园区人员进出管理。

## 答辩高频问题

### 问：如何避免围栏误触发？

答题思路：

- 不用单点判断。
- 结合连续点、停留时间、定位精度。
- 使用缓冲区和状态机。
- 对事件做冷却和去重。

### 问：大量围栏如何高性能判断？

答题思路：

- 围栏建空间索引。
- 点上报时先召回候选围栏。
- 对候选做精确点面判断。
- 用缓存保存对象状态。
- 事件异步化。

### 问：点在多边形边界上算不算在内？

答题思路：

- 技术上要有明确规则。
- 业务上通常结合缓冲区处理。
- 关键是保证服务行为一致且可解释。

## 本节总结：答辩突击记忆清单

- 地理围栏 = 空间边界 + 位置流 + 状态机 + 事件。
- 围栏类型包括圆形、多边形、行政区、线缓冲区。
- 围栏判断不能只看单点，要看连续状态。
- 定位抖动要用连续命中、停留时间、缓冲区、冷却和状态机处理。
- 大量围栏需要空间索引和异步事件系统。
- 围栏服务必须关注版本、幂等、去重和可回放。

如果只准备一个案例，就讲“骑手到店围栏如何设计”，这是最容易把技术和业务讲完整的题。
